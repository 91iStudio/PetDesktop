# Пушиши на рабочем столе

Маленький питомец из игры [pet.91i.ru](https://pet.91i.ru) гуляет по панели задач Windows.
Это открытый код приложения: его можно прочитать и собрать самому.

## Что приложение делает

- Показывает питомца поверх панели задач: гуляет, моргает, спит у часов, радуется, когда его гладят мышкой,
  его можно взять и перенести.
- Раз в 12 минут обращается к `pet.91i.ru` — и **только** туда: узнать, какой у вас питомец и как он себя чувствует,
  скачать его картинку и отправить, сколько раз его погладили и сколько минут он был на экране.
- Хранит картинку и настройки в `%LOCALAPPDATA%\91iPet`.

## Чего приложение не делает

- Не читает ваши файлы, буфер обмена и список программ.
- Не требует прав администратора и не устанавливается: один exe, удаляется вместе с папкой
  (и `%LOCALAPPDATA%\91iPet`).
- Не запускается само, пока вы не включите «Запускать вместе с Windows» в меню.
- Когда на экране игра, фильм или презентация во весь экран, питомец прячется. Это определяется только у вас
  на компьютере (функция Windows) и никуда не сообщается.

## Как убедиться

В меню у часов (правая кнопка по значку или по питомцу):

- **Что я отправлял** — журнал каждого запроса: когда, куда и что именно ушло (ключ приложения показан не целиком).
- **Нагрузка на компьютер** — сколько памяти и процессора занято прямо сейчас. Когда питомец стоит, он перерисовывается
  раз в несколько секунд (моргает); когда спит или вы играете во весь экран — ни разу.

## Привязка

Пароль в приложение не вводится. На сайте в меню выберите «Питомец на рабочем столе» — там будет код из 6 цифр,
его и нужно ввести в приложении. У приложения свой ключ, отдельный от браузера.

## Сборка

Нужен [.NET SDK 10](https://dotnet.microsoft.com/download) — ровно той версии, что в `global.json` (иначе exe соберётся, но побайтово будет другим).

```
dotnet publish -c Release -o out
```

Получится `out/Pushishi.exe` — один файл, .NET внутри, ничего ставить не нужно.
С установленными инструментами C++ из Visual Studio можно собрать нативный exe поменьше: `-p:Aot=true`.
В релизе он лежит рядом: `Pushishi-native.exe` (пробный: меньше и легче, .NET внутри нет).

Для проверки на своём сервере: переменная окружения `PUSHISHI_SITE` (например `http://localhost:5000`) меняет адрес сайта.

## Как проверить, что exe собран из этого кода

Готовые exe собирает не человек, а GitHub Actions (`.github/workflows/release.yml`) из коммита с тегом `v…`.
К каждому exe GitHub выпускает подписанное подтверждение происхождения (attestation): «этот файл собран из такого-то
коммита этим сценарием». Файл, скачанный откуда угодно (со страницы релиза или с pet.91i.ru), проверяется так:

```
gh attestation verify Pushishi.exe --repo 91iStudio/PetDesktop
```

Или проще — сравнить SHA-256 с `SHA256SUMS.txt` в релизе и в журнале сборки. Можно и собрать самому той же командой, что в
`.github/workflows/release.yml`, тем же SDK — хеш совпадёт бит в бит (проверено на v0.2.0):

```
certutil -hashfile Pushishi.exe SHA256
```

Сайт раздаёт ровно тот же файл, что лежит в релизе на GitHub (тот же SHA-256).
